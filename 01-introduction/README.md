# Module 01: Introduction & Foundations

Foundational concepts, communication paradigms, ambiguity navigation, and diagramming standards for System Design interviews.

---

## 📚 Lessons in this Module

1. [**01: What is System Design?**](./01-what-is-system-design.md) — Fundamental motivation, distributed scale limits, and core pillars.
2. [**02: Why System Design Matters**](./02-why-system-design-matters.md) — Senior vs junior engineering mindsets and interview evaluation rubrics.
3. [**03: Distributed Systems Overview**](./03-distributed-systems-overview.md) — Fallacies of distributed computing, physics limits, and core theorems.
4. [**04: System Design vs Low-Level Design**](./04-system-design-vs-low-level-design.md) — HLD vs LLD boundary, architecture vs object-oriented design.
5. [**05: System Design vs Coding Interviews**](./05-system-design-vs-coding-interviews.md) — Transitioning from DSA problem solving to architectural dialogue.
6. [**06: How to Approach Ambiguous Problems**](./06-how-to-approach-an-ambiguous-problem.md) — The Ambiguity Funnel and functional scoping protocols.
7. [**07: How to Communicate Architecture**](./07-how-to-communicate-architecture.md) — Top-down communication hierarchy and structured justification formulas.
8. [**08: How to Reason About Trade-offs**](./08-how-to-reason-about-trade-offs.md) — Classic architectural dilemmas (Push vs Pull, CP vs AP, Latency vs Durability).
9. [**09: Interview Time Management**](./09-interview-time-management.md) — The 45-minute game clock and phased execution checklists.
10. [**10: Architecture Diagramming Standards**](./10-architecture-diagramming.md) — Visual contracts, component naming, and Mermaid diagramming best practices.
